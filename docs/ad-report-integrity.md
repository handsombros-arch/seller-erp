# 쿠팡 광고 보고서 원본 보존

2026-10-02 로컬 수정. 운영 배포 및 운영 데이터 재업로드는 아직 검증하지 않음.

## 원인과 수정

기존 날짜·키워드·전환 옵션·노출 지면 키는 원본 행의 고유 식별자가 아니다.
광고집행 옵션이 다르거나, 모든 식별 항목이 같고 실적만 다른 행도 존재한다.
파일 내부에서는 같은 키의 행을 모두 보존한다. 파일 간 재업로드는 같은 키의
실적 묶음을 교체한다. 입력 기준은 전체 캠페인의 일별 키워드 보고서이며,
같은 날짜를 여러 파일로 나눈 부분 보고서를 합치는 용도로 사용하지 않는다.

기존 DB 키를 유지하고 복수 원본 행은 JSON의 __adSourceRowsV2에 함께 저장한다.
서버 조회 시 원본 행으로 다시 펼친다. 클라이언트는 묶음을 만든 다음 전송을
분할하므로 한 묶음이 여러 요청에 걸쳐 잘리지 않는다. 기존 1행 데이터는
그대로 읽으며, 원본 재업로드 시 같은 DB 키를 갱신하므로 이중 저장하지 않는다.
브라우저 캐시의 서버 이전은 기존처럼 insert-only이고 새 보고서만 갱신한다.

DB 통계의 rawRowsCount는 저장된 묶음 개수이며 화면 및 일반 GET의 totalRows는
원본 행 개수다. 두 값이 다른 것은 정상이다. 응답 inserted는 신규 삽입 수가
아닌 성공적으로 저장을 시도한 묶음 수다.

## 검증

scripts/test-ad-sync.cjs: 원본 충돌 보존, 재업로드, 기존 데이터 복구,
수정 보고서 교체, 전송 분할, 서버 저장 및 재조회, 실패 시 500 응답.
선택적으로 첫 인자에 실제 원본 엑셀 경로를 전달한다.

2026-10-01 실제 파일: 4,117행, 노출 539,250, 클릭 1,722,
광고비(VAT 제외) 243,061원, 14일 주문 39건, 원본 전환매출 1,097,980원.
저장·조회·재업로드 후 위 수치가 모두 동일함을 검증했다.
ERP 상품별 매출 보정 및 VAT 포함 표시와는 별도의 원본 합계다.

전체 타입 검사는 기존 HEAD와 변경본 모두 22개 오류이며 새 오류는 없다.
프로젝트는 기존 설정으로 빌드 시 타입 오류를 무시한다.

## 운영 반영

화면과 API를 함께 배포한 다음 전체 캠페인 원본을 다시 업로드하고,
새로고침 및 다른 브라우저에서 행 수와 원본 합계를 확인해야 한다.
이미 버려진 원본 행은 코드 배포만으로 복구되지 않는다.
